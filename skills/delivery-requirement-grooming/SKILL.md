# 梳理需求阶段

任务面板四个技能中的第二个，负责单条任务的 `phase=requirement` 回合。

| 技能 | 负责 |
| --- | --- |
| `delivery-task-planner` | 把需求拆成任务并写入面板 |
| **`delivery-requirement-grooming`** | **本技能：把一条任务梳理成需求文档** |
| `delivery-action-execution` | 按文档实现并交付产物 |
| `delivery-testing-report` | 验收产物并产出测试报告 |

## 会话前提

- 这一轮由任务面板的执行桥发起，任务已经被领取并绑定到当前会话。
- 不要调用 `claim_next_task`、`bind_task_execution_session`、`finish_execution_task` 或任何任务状态流转工具；桥接器按本回合的最终状态自动同步面板。
- 不要调用 `create_task_board_*` 创建新任务：本阶段不扩充任务清单，发现缺口写进文档的「后续任务建议」，由用户回需求拆解会话处理。
- 阶段推进（梳理需求 → 动作执行）是用户在面板上的动作，不要自行推进，也不要在本轮顺手把开发做了。

## 1. 先读已有上下文

提示词会给出需求文档路径，形如 `doc/<模块>/<任务键>/文档.md`。

- 文件已存在：读它，本轮是增量修订，保留仍然成立的结论，改写过时部分。
- 文件不存在：本轮创建。
- 同时读任务标题、说明、里程碑、模块和前置任务；前置任务的文档往往已经定好了本任务要对接的接口和字段。
- 提示词里会给出「本需求下其他任务已写好的需求文档」清单（任务键、标题、是否前置、文档路径）。这是**按需加载**的索引，不是让你全读：
  - 标了「前置依赖」的先读——本任务要对接的接口、字段和数据结构通常已经在那里定死了。
  - 其余的按标题判断，只打开与本任务有接口、数据口径或产出衔接关系的那几份。
  - 无关的不要读，上下文留给真正要干的活。读了哪几份、为什么读，在最终回复里说一句。

## 2. 核实工程事实，不要凭空写

需求文档的价值在于「基于当前代码的事实」。动手写之前先查：

- 提示词给出的「项目工作目录」就是项目管理里为本项目绑定的代码仓库，也是本轮 cwd；先加载该目录下的项目开发技能再开始查。
- 相关目录、现有实现、命名与分层约定（后端看 `backend-development`，前端看 `web-development` 这两个项目技能）。
- 已有接口、表结构、配置项的真实形态，用文件路径作为依据。
- 与本任务冲突或重复的既有实现。

写不准的地方标成「待确认」，不要编造文件名、字段名或接口路径。

## 3. 产出文档

`doc/<模块>/<任务键>/文档.md` 用中文写，建议结构：

1. **任务目标**：一句话说清做完之后什么变了；并写明本阶段只做梳理。
2. **当前工程事实**：表格列「项目 / 结论 / 依据」，依据必须是仓库里的真实路径。
3. **需交付的内容**：按文件或模块列出要新增、修改、废弃的东西。
4. **设计要求**：接口、数据结构、交互、错误处理、兼容性，能定死的就定死。
5. **约束与非目标**：明确不做什么，避免动作执行阶段扩散。
6. **验收标准与测试准备**：每项写成可验证的「条件/输入、操作、预期结果、观测方式」，并列出测试对象与必要顺序。若需要接口 Token、测试账号/角色、初始数据、素材、外部服务、环境地址或清理动作，写明用途、受控来源和缺失项；绝不把密码、Token 等秘密写进文档。
7. **风险与待确认**：阻塞项、需要用户拍板的选择。

范围小的任务可以合并小节，但「验收标准与测试准备」永远保留；不适用的准备项明确写“无”。

### 原型图生成任务

如果面板上下文明确标记当前任务是「原型图生成任务」，本轮除了需求文档外还必须生成真实的原型图资产：

- 使用可用的图像生成能力，不能只在文档中描述界面；
- 存到 `doc/<模块>/<任务键>/prototype/`，至少一张 PNG、JPG、WEBP 或 GIF；
- 图片只作为该任务文档的附属材料，不修改业务代码；
- 最终回复列出图片的工作区相对路径，任务详情会据此目录提供「打开原型图目录」。

## 4. 结束本轮

- 优先自己把文档写进工作区文件；最终回复给一段摘要，并用 Markdown 链接列出文档的工作区相对路径。
- 如果没有落文件，桥接器会把最终回复原样写进该路径。因此最终回复不能只写「已完成」，那会变成文档正文。
- 只改文档和 `doc/` 下的附属材料，不改业务代码；确实需要试探性验证时用只读命令。
- 无法完成时说明阻塞原因，不要用猜测填满文档。
