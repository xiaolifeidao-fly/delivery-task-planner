# 测试用例设计模式

什么时候读：桥接提示词写明本轮是**测试用例设计模式**时。执行验收模式不看本文件。

本模式只设计用例，绝不执行任何真实验证。


1. 按提示词给出的顺序取需求：提示词说需求级文档 `doc/requirements/<需求键>/需求大纲.md` 存在时先读它的「摘要」和「范围与不做的事」，再按本任务涉及的部分下钻到相关章节，其次是提示词说存在的 `doc/<模块>/<任务键>/文档.md`（这份是直接依据，正常篇幅就整份读完）；提示词说任务需求文档不存在时，直接以提示词里的「任务说明」为准，不要自己判断文件在不在。再按真实代码、路由、前端调用、现有测试和关联任务建立测试对象；研发尚未完成的部分标为“执行前置/待补输入”，不可猜造实现结果。
2. 逐条拆验收标准，形成用例表：**编号 / 关联验收项 / 对象类型 / 前置与数据 / 操作顺序 / 预期 / 证据要求 / 执行前置**。接口必须列方法、鉴权来源类型、依赖实体、请求样例形状和关键断言；UI 列账号角色、初始状态和页面路径；脚本/媒体列输入、输出和核验方式。
3. 将跨接口、跨任务和端到端链路按真实依赖排序；明确 Token、账号、环境、测试数据、外部依赖、素材和清理方案的缺口。凭据只写来源类型，绝不写值。
4. 写入 `doc/test/<任务键>/测试用例.md`，按需写 `测试计划.md` 或其他补充测试文档；该目录支持多份文档。此模式只允许设计文档；不要创建 `测试报告.md`、脚本、夹具或证据文件。
5. 最终回复第一行必须且只能是：`测试用例已生成`。随后简述已覆盖范围、用例数量、执行顺序和待补条件；不要给出“验收判定”。
