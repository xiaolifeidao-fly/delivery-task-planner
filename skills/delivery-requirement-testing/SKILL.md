# 需求测试用例与总体测试

这是**需求维度**的测试工作：先可与研发并行设计用例，再验证多个关联任务是否共同满足一条需求的业务目标、跨任务接口和端到端路径。不要把它当成某个任务的成品测试，也不要重新执行无关任务的全量回归。

## 选择本轮模式

桥接提示词会指定模式，必须严格遵守。

| 模式 | 工作边界 | 产物 |
| --- | --- | --- |
| **测试用例设计模式** | 读取需求、关联任务、代码和已有产物，设计关联任务、跨任务顺序、测试数据、环境、账号/Token 来源、步骤、预期和证据；**不得执行**接口、UI、脚本或构建，也不得写验收判定/报告 | `doc/test/<需求键>/测试用例.md`，按需 `测试计划.md` |
| **执行验收模式** | 先读已有用例，再真实准备、执行、取证、对比和判定 | `doc/test/<需求键>/测试报告.md` 及脚本、夹具、证据 |

## 按需下钻：references/

本文件只保留两种模式都要守的边界。具体怎么做按模式分文件放在 `references/` 下，**只读本轮那一份**：

| 文件 | 什么时候读 |
| --- | --- |
| `references/用例设计模式.md` | 提示词写明本轮是测试用例设计模式 |
| `references/执行验收模式.md` | 提示词写明本轮是执行验收模式 |

模式互斥，另一份这一轮一个字都用不上，不要两份都读。

## 最终回复的第一行

- 测试用例设计模式：第一行必须且只能是 `测试用例已生成`，不得给出验收判定。
- 执行验收模式：第一行必须且只能是下列之一。

```text
验收判定：通过
验收判定：不通过
验收判定：受阻
```

## 固定边界与产物

- 提示词会给出需求详情、所属项目、关联任务清单和每项任务的文档/产物路径；先读这些事实，再从代码、路由、调用链和交付物确定整体测试范围。
- 本轮只做总体测试和报告，不修改业务实现；发现缺陷要精确定位回对应任务或代码位置。
- 所有本轮测试资产必须放在项目工作目录的 `doc/test/<需求键>/`，其中 `<需求键>` 使用面板给出的 `requirementKey`。
- `doc/test/<需求键>/` 是支持多份文档的需求级测试目录；除固定的 `测试用例.md`、`测试计划.md`、`测试报告.md` 外，补充测试说明使用独立稳定文件名。需求大纲仍位于 `doc/requirements/<需求键>/`，需求原型仍位于其 `prototype/` 子目录，两者不要混写测试资产。
- 设计模式至少写入 `测试用例.md`；执行模式写入 `测试计划.md` 和 `测试报告.md`。测试脚本放 `scripts/`、脱敏夹具放 `fixtures/`、截图/日志/样本放 `evidence/`。不要创建空目录，不要写入密码、Token、Cookie、私钥或生产个人数据。
- 需求总体报告会同步到需求右侧的“测试报告”视图；任务级报告仍只挂在各自任务上，两者不可互相覆盖。
