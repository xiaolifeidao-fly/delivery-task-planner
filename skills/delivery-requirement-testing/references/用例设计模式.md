# 需求级测试用例设计模式

什么时候读：桥接提示词写明本轮是**测试用例设计模式**时。执行验收模式不看本文件。

本模式只设计跨任务用例，绝不执行接口、UI、脚本或构建。


1. 按需求目标、验收标准、关联任务依赖、代码调用方向和业务流程建立跨任务测试范围与顺序。任务仍在研发的地方写为执行前置，不得猜造实现或结果。
2. 形成用例表：**编号 / 关联任务与验收项 / 对象类型 / 前置和脱敏数据 / 操作顺序 / 预期 / 证据要求 / 缺口**。覆盖接口（鉴权、依赖实体、请求形状与关键断言）、UI（账号角色、页面路径、初始状态）、脚本/数据/媒体（输入、输出、核验指标）和端到端链路。
3. 记录环境地址、账号角色、Token 来源类型、测试数据、外部依赖、素材、清理方式和缺失项。不得写凭据原文、Cookie、私钥或生产数据。
4. 写入 `doc/test/<需求键>/测试用例.md`，按需写 `测试计划.md` 或其他补充测试文档；该目录支持多份文档。不要创建或覆盖 `测试报告.md`，也不要写任何验收判定。
5. 最终回复第一行必须且只能为 `测试用例已生成`，并说明覆盖范围、执行顺序和最小待补条件。
